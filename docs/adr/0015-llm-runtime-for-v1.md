# LLM runtime for v1

Live Hard Constraint / Preference / Relevance judging and Prepare (Gap Report / Tailored CV / Edit Summary) use one **OpenAI-compatible** HTTP client. Credentials and model come from the environment only: `JOB_FINDING_ASSISTANT_LLM_API_KEY` (required for live calls), optional `JOB_FINDING_ASSISTANT_LLM_BASE_URL` (default OpenAI), and `JOB_FINDING_ASSISTANT_LLM_MODEL` (one model for both `LlmJudge` and `LlmCvTailor`; default when unset e.g. `gpt-4.1-mini`). No key or model UI, no disk-stored secrets, no multi-provider SDK surface in v1.

There is **no offline fallback** beyond existing failure rules: LLM Unavailable → required judgments stay **Pending** or keep the prior complete assessment ([0014-assessment-freshness-and-change-detection.md](0014-assessment-freshness-and-change-detection.md)); tailor mid-run failure leaves any prior Preparation Packet untouched ([0013-prepare-flow.md](0013-prepare-flow.md)). No local model, no heuristic scorer, and **Fake is never wired into the normal app path** (Fake stays for tests). Missing key means unavailable, not scripted bands. No budget meter, spend cap, or batch-confirm for cost in v1 — document that assess/Prepare call the live API. The catalog (and Prepare when relevant) shows a short non-secret **LLM Unavailable** reason; never show the key.

**Considered Options:** Multi-provider UI / native Anthropic or Google SDKs; API key or model picker in settings; Fake-when-unset so the UI always “works”; local/Ollama offline path; spend caps or confirm-before-batch-rejudge. Rejected multi-provider and settings UI for a single-user local tool; rejected Fake-when-unset because scripted assessments look live; rejected offline scorers so bands stay rubric-honest; rejected cost UI as fake precision without changing Pending behavior.
