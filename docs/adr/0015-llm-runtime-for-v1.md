# LLM runtime for v1

Live Hard Constraint / Preference / Relevance judging and Prepare (Gap Report / Tailored CV / Edit Summary) use one **OpenAI-compatible** HTTP client. Credentials and model come from the environment only: `JOB_FINDING_ASSISTANT_LLM_API_KEY` (required for live calls), optional `JOB_FINDING_ASSISTANT_LLM_BASE_URL` (default OpenAI), and `JOB_FINDING_ASSISTANT_LLM_MODEL` (one model for both `LlmJudge` and `LlmCvTailor`; default when unset e.g. `gpt-4.1-mini`). No key or model UI, no disk-stored secrets, no multi-provider SDK surface in v1.

OpenAI-compatible hosts (e.g. DeepSeek) need their own model id — do not leave the OpenAI default when pointing elsewhere. Example: `JOB_FINDING_ASSISTANT_LLM_BASE_URL=https://api.deepseek.com` and `JOB_FINDING_ASSISTANT_LLM_MODEL=deepseek-chat` (or the host’s current chat model).

**LLM Run (Assessment Summary activity):** Catalog load (`GET /` / `load_assessment_summary_catalog`) is **fast** — it does **not** run a Pending judge batch. The user **explicitly starts** a catalog assess **LLM Run** (or starts **Bulk Prepare**, which is also an LLM Run). At most **one** LLM Run is in flight at a time; a second start is refused or waits with a clear “already judging/preparing…” message. Implementation: process-local run with a thin **status poll** (phase `Judging` / `Preparing`, Job Posting identity, `k of n` for this run) and a **Stop** flag; Assessment Summary only — not Match Assessment detail, not Master CV Enrichment progressive UI in this decision. Catalog assess attempts **at most five** Pending Job Postings per LLM Run (sequential; each saved/skipped/non-unavailable failure consumes one unit; user starts again to continue). Bulk Prepare stays uncapped per ADR-0013. On **LLM Unavailable** for an attempt, stop the rest of that run early. A judge failure or skip must **not** starve later Pending ids: the process defers the failed head and advances the queue, then retries deferred heads after a full pass. **Stop** or leave/refresh: cooperative abort — finish the **current** posting’s provider call and apply normal success/failure rules; do **not** start the next; keep successes already saved; no auto-resume of the interrupted run. HTTP calls use a short timeout and map timeouts to **LLM Unavailable**. Opportunistic rejudge after Crawl / file change (`rejudge_pending_assessments`) stays at **one** Pending per call with **no** LLM Run banner — do not stack Playwright Crawl with a five-call assess run. No spend meter, ETA, or cost UI.

There is **no offline fallback** beyond existing failure rules: LLM Unavailable → required judgments stay **Pending** or keep the prior complete assessment ([0014-assessment-freshness-and-change-detection.md](0014-assessment-freshness-and-change-detection.md)); tailor mid-run failure leaves any prior Preparation Packet untouched ([0013-prepare-flow.md](0013-prepare-flow.md)). No local model, no heuristic scorer, and **Fake is never wired into the normal app path** (Fake stays for tests). Missing key means unavailable, not scripted bands. No budget meter, spend cap, batch-confirm, disk-stored API keys, or key UI — credentials remain env-only; document that assess/Prepare call the live API. The catalog (and Prepare when relevant) shows a short non-secret **LLM Unavailable** reason; never show the key.

**Considered Options:** Multi-provider UI / native Anthropic or Google SDKs; API key or model picker in settings; keys config file on disk; Fake-when-unset so the UI always “works”; local/Ollama offline path; spend caps or confirm-before-batch-rejudge; spend/activity meter as the primary ops UX; background / unattended rejudge; until-empty catalog assess; keeping Pending judge batch on `GET /`; raising Crawl-path rejudge to five; parallel judging in this ship; hard-cancel of the in-flight provider HTTP call; progressive LLM Run UI on Match Assessment single Prepare / Enrichment. Rejected multi-provider, settings UI, and disk-stored keys for a single-user local tool (env-only); rejected Fake-when-unset because scripted assessments look live; rejected offline scorers so bands stay rubric-honest; rejected cost/spend UI (provider billing site is enough); rejected background unattended rejudge and until-empty to keep spend user-triggered and bounded; rejected judge-on-`GET /` because multi-minute sequential calls freeze the catalog — explicit start + live status instead; rejected Crawl-path budget of five so Playwright Crawl is not stacked with a long judge batch; rejected parallel judging for this ship (park for later); rejected hard provider abort in favor of cooperative Stop; deferred Prepare/Enrichment progressive UI as thin reuse later. Fixed catalog assess budget of five chosen over one to cut “start again” churn while staying predictable.
