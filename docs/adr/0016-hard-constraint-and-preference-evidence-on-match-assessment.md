# Hard Constraint Evidence and Preference Evidence on Match Assessment

v1 Match Assessments stored short Hard Constraint / Preference reasons and Relevance **Evidence** only; judge ports already returned light Evidence-style pairs for Hard Constraint and Preference (ADRs 0008 / 0010) but those lists were dropped on save. We now **persist and show** Hard Constraint Evidence and Preference Evidence on the Match Assessment detail page (same Evidence-pair shape; counterpart is a Hard Constraints or Preferences line, never CV), so Prepare-vs-skip justification matches what the judge already produced. Empty lists are allowed (e.g. Hard Constraint pass); do not invent padding pairs; existing complete rows stay empty until a natural rejudge. Assessment Summary stays bands-only; Preparation Packet keeps a compact current-assessment strip with a link to Match Assessment for the lists. Accordion / richer nav stays parked. Rubric when to emit pairs remains in [0008-preference-and-relevance-judge-rubrics.md](0008-preference-and-relevance-judge-rubrics.md) and [0010-hard-constraint-judge-rubric.md](0010-hard-constraint-judge-rubric.md).

**Status:** accepted (implemented; GitHub #19)

**Considered Options:** Keep reasons-only; regenerate Evidence on read without storing; put full Evidence lists on the Preparation Packet page. Rejected reasons-only because the pairs were already computed and Prepare decisions need them; rejected regenerate-on-read as a second source of truth beside the saved assessment; rejected packet-full-lists so Gap Report → Edit Summary → Tailored CV review stays the prepare path and Match Assessment remains the fit view.
