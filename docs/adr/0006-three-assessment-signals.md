# Three assessment signals: Hard Constraint, Preference, Relevance

Match Assessment uses three distinct signals: Hard Constraint (deal-breaker signal — pass/fail/unknown), Preference (do I want this? — ordinal Strong/Mixed/Weak from the Preferences file), and Relevance (does my experience match the JD? — ordinal Strong/Mixed/Weak from Master CV / Snapshot). Vendor-style ATS scores and 0–100 Preference Scores were rejected as marketing-ish or falsely precise. Preference and Relevance are not the same concept. Sort: Pending last, Hard Constraint fail after pass/unknown, then Preference, then Relevance, then sooner deadline; unknown Preference ties so Relevance decides. Prepare is blocked only while Pending; Hard Constraint fail never blocks Prepare (confirm with reason — see [0013-prepare-flow.md](0013-prepare-flow.md)); a separate Override action was rejected. Preference Weak does not block Prepare. Scoring criteria for Preference and Relevance bands are in [0008-preference-and-relevance-judge-rubrics.md](0008-preference-and-relevance-judge-rubrics.md). Hard Constraint judge criteria are in [0010-hard-constraint-judge-rubric.md](0010-hard-constraint-judge-rubric.md).
